Cost Optimization

成本优化方案

当前架构下一次 /deep 完整调用约 ¥1.50，主要成本在 Layer 2 顺序辩论的 Opus 调用 + 指数级增长的上下文。按 ROI 排序的 8 个优化方向，预计可将单次成本降至原来的 30%。

当前成本构成

Layer 2 辩论（瓶颈）
~55%
7 次 Opus 调用，上下文指数增长
Layer 1 并行
~25%
8 个分析师 × Sonnet
Synthesizer
~15%
Opus + 全部上下文
Router LLM
~5%
策略匹配 + LLM 精选

高性价比方案（立即可做）

#1

Prompt Caching（Anthropic 原生）

-30~50%

问题：Layer 1 每个分析师的 system prompt 长达 50-80 行（数千 token），每次调用都全量计费。

方案：在 ai-gateway.ts 为 Anthropic 调用添加 cache_control: { type: "ephemeral" }。

收益：Cache hit 后 system prompt 费用降至 10%，同会话内重复调用几乎免费。
#2

Layer 2 上下文压缩

-25%

问题：第 7 位大师接收 Layer 1 全文（~8K tokens）+ 前 6 位大师发言（~6K tokens）= 14K input，是第 1 位的 3 倍。

方案：Layer 1 → Layer 2 只传 summary + keyPoints + sentiment，不传 fullReport；前序大师发言只传 stance + 核心论点前 200 字。

收益：Layer 2 input tokens 降 60-70%，Opus 输入费用降约 50%。
#3

分层模型路由（Opus → Sonnet 降档）

-40~50%

问题：7 位大师全用 Opus，但补充和回应类 stance 并不需要 Opus 级别深度。

方案：按 stance 分配模型：立论/质疑/挑战 3 位用 Opus（价值守门人、周期判官、生意模式派），其余 4 位用 Sonnet。

收益：Layer 2 费用降 40-50%（Opus 约是 Sonnet 5x）。

中等收益方案

#4

Layer 1 智能裁剪

-50~60%

问题：不管问什么都跑 8 个分析师，但"NVDA 新闻摘要"不需要 Wanda 组合策略。

方案：意图识别前置，按查询类型选 Layer 1 子集（宏观 3 位 / 估值 4 位 / 技术 3 位 / 全面 8 位）。

#5

Layer 1 结果缓存

热门股 ≈ 0

问题：同一股票短时间内反复调用会重复跑 Layer 1。

方案：建 layer1_cache 表，key = symbol + date + agent，同日命中直接复用，TTL 30 分钟。

#6

Synthesizer 输入精简

-70% input

问题：Synthesizer 接收 L1 + L2 全文，是单次 input 最多的调用。

方案：只传情绪分布、共识点、分歧点、立场矩阵和每位大师核心论点前 300 字。

结构性优化（需改架构）

#7

Layer 2 两轮并行

延迟 -60%

问题：7 次顺序调用，延迟累加且 context 爆炸。

方案：第一轮 3 位并行（价值、成长、周期）看 L1；第二轮 4 位并行看第一轮结果。牺牲少量辩论连贯性换取 60% 延迟 + 40% token 节省。

#8

Router 规则优先

-70% LLM 调用

问题：Router 也用 LLM 判断，但很多场景规则就能覆盖。

方案：扩展策略表，绝大部分走规则匹配，仅当候选大师 > 5 且 use_router_llm=true 才调 LLM。

综合估算（叠加效果）

方案 边际节省 累积后单次成本

Design Philosophy

核心设计原则

这些不是功能，是产品的灵魂。

⚔️

强制对抗机制

即使所有分析师都看多，系统自动调高周期判官和反身性猎手的质疑力度。不允许一边倒，确保辩论质量。

🛡️

Thor 硬约束

风控 Agent 的仓位上限是铁律。Wanda（组合策略）不能突破 Thor 设定的上限。分析再好，风控说空仓就空仓。

🏷️

数据标注纪律

所有输出必须标 [数据]（系统提供）vs [推断]（AI 推理），从根源上防止 AI 幻觉被当成事实。

🔄

并行 + 顺序双模

Layer 1 并行（快），Layer 2 顺序辩论（每人读到前面所有人发言）。兼顾速度和辩论深度。

💡

哲学编码

每位大师有明确投资哲学（Graham、Lynch、Soros 等），辩论时必须引用自身哲学框架，不是泛泛而谈。

🎭

角色化表态

立论 / 补充 / 质疑 / 反驳 / 挑战 / 裁定，辩论角色是程序化分配的，不是自由发挥。

⑤ 数据同步策略（关键决策点）
Pathfinder 是独立 Python 进程，sector_signal_latest.json 原本是文件系统缓存。接入 ARTI 有 3 个方案：
方案 优点 缺点 推荐度
A · 写入 Supabase 表 Edge Function 直接查库，低延迟，无网络依赖 Pathfinder 端需要改造，双写 JSON + DB ⭐⭐⭐⭐⭐
B · HTTP API 暴露 Pathfinder 不用改 引入网络依赖，Edge Function 要处理超时 ⭐⭐
C · 上传 Supabase Storage 改动最小 Edge Function 额外一次 fetch ⭐⭐⭐
强烈推荐方案 A：Pathfinder 的 build_sector_rotation_signal 等函数在写 JSON 的同时，再写一份到 Supabase 表（sector_signals / stock_pool_snapshots / daily_briefs）。这样 ARTI Edge Functions 只需要查库，不依赖外部服务。

Competitor Analysis

竞品对比：ARTI vs RockFlow

RockFlow 是新加坡 AI 投资平台，持 NZ FSP 牌照，支持美港股交易。以下从产品定位到技术架构逐项对比。

ARTI
定位：机构级 AI 投研平台
核心：双层 Multi-Agent 辩论 → 深度研报
用户：高净值投资者、专业投研人员
模式：投研分析 → 信任建立 → 持牌产品导流
市场：A 股 + 港股 + 美股
交易：不做交易，纯投研工具
AI：8 分析师 + 7 大师顺序辩论 + 最终裁定
RockFlow
定位：AI 原生零售券商
核心：Bobby AI Agent → 对话式交易闭环
用户：年轻散户、Gen Z、初级投资者
模式：$1 起投 + 跟单 + 佣金/利差
市场：美股 + 港股（30+ 国家）
交易：自营券商，支持交易执行
AI：单一 Agent Bobby（多模型底座：DeepSeek/Claude/GPT）
维度 ARTI RockFlow
AI 架构 双层 Multi-Agent：8 并行分析师 + 7 顺序辩论大师 + 合成器。每位大师有独立哲学和辩论角色，真实看到前序发言 单一 Agent Bobby，多模型底座（DeepSeek/Claude/GPT）。大模型负责语义，金融工程处理交易逻辑，风控规则防幻觉
分析深度 优势 — 多视角辩论（价值/成长/周期/反身性/宏观/配置/模式），强制观点碰撞 单一 Agent 给出建议，无多角度交叉验证。偏向通俗化解释，降低信息密度
交易闭环 无交易功能，纯投研工具。需跳转第三方完成交易 优势 — 对话即交易。语音/文字下单 → AI 执行 → 自动止盈止损，分析-交易完整闭环
社交功能 讨论组后端已就绪，前端未上线。无跟单功能 优势 — RockStar 排行榜 + 一键跟单 + 策略市集，社交飞轮成熟
A 股覆盖 优势 — AKShare + 财联社 + 新浪财经，北向资金/融资融券/板块资金流全覆盖 不支持 A 股交易和数据
个性化 无用户偏好系统，所有人看到相同分析 优势 — Bobby 理解"买一点"因人而异（5% 仓位 vs 1 股 vs $100），基于用户资产和行为个性化
数据壁垒 Finnhub + Yahoo + AKShare，定时刷新到 Supabase。数据源公开可获取 优势 — 三层数据：金融工程数据（需资质）+ 场景数据（社媒/新闻）+ 个性化数据（用户行为），自有交易数据构建壁垒
用户门槛 优势 — 面向专业投资者，高信息密度输出。DL Holdings 持牌背书 面向小白，$1 起投，游戏化 UI。NZ FSP 牌照 + SIPC $50 万保险
推送触达 无主动推送，用户需主动访问网页 优势 — App 推送 + TradeGPT 每日机会推荐 + 社媒信号实时提醒
从 RockFlow 学到的精进方向
1. 分析 → 行动的断裂
ARTI 出了深度研报，用户需要自己去别的平台下单。RockFlow 的对话即交易是杀手级体验。方案：至少接入模拟交易 / 一键跳转合作券商下单页
2. 缺少个性化理解
Bobby 知道用户的资产规模、风险偏好、交易习惯，ARTI 完全不知道。方案：新建用户画像系统（偏好市场、持仓、风险等级），注入大师辩论上下文
3. 社交/跟单飞轮缺失
RockFlow 的 RockStar 排行 + 一键跟单形成用户留存飞轮。ARTI 的讨论组后端已有但前端未上线。方案：优先上线讨论组 + 观点排行 + 分析结果分享链接
4. 被动触达能力为零
RockFlow 有 App 推送 + TradeGPT 每日推荐。ARTI 用户不打开网页就收不到任何信息。方案：Telegram Bot 每日情报推送（已加入 P1 TODO）+ Web Push 通知
5. 移动端体验差距
RockFlow 是移动端优先（原生 App），ARTI 是 Web 适配移动端。金融产品的核心场景在手机上。方案：短期做 PWA，中期考虑 React Native 原生 App
6. ARTI 的不可替代优势
双层辩论是 RockFlow 没有的。Bobby 是单一 Agent 给建议，ARTI 是 7 位大师真实碰撞观点。这是核心壁垒，应持续强化辩论质量而非追求交易闭环。

借鉴 Day1 的多哲学视角验证矩阵，在圆桌输出中增加结构化的观点矩阵表：同一关键问题（护城河强度、估值合理性、最大风险）下 7 位大师分别怎么看，让分歧一目了然。改动范围：修改 roundtable.py 输出 schema + 前端展示。
P2 Synthesizer 加入 Pre-Mortem 分析
借鉴 Day1 的反偏见框架，在最终裁定中加入 Pre-Mortem 段落：「如果这笔投资一年后亏损 30%，最可能的原因是___」。虽然 Marks 和 Soros 已承担部分反偏见角色，但 Synthesizer 层面的系统性总结能进一步降低确认偏误。改动范围：修改合成器 prompt。
P3 证据分层标注体系
借鉴 Day1 的三层证据标准（一手来源 > 事实来源 > 观点来源），在大师输出中要求标注关键论据的来源类型。提升报告专业度和可信度。改动范围：修改 common.ts 通用规则 + layer2 prompt。
结论
Day1Global-Skills 综合评分 7.5/10，本质是一套高质量的「投研 Prompt 工程模板」。在工程架构（Multi-Agent 辩论、真实数据源、自动化管线）上 ARTI 远超对方。但 Day1 的分析框架颗粒度是最大亮点——16 个模块的操作级检查清单、反偏见框架、证据分层标准值得吸收。核心策略：保持我们的架构优势，用 Day1 的细粒度框架补强 prompt 的「操作层」深度。

Part 7 · 关键注意事项与踩坑预警

orchestrator 是超长任务（120-300s）
Edge Function 硬上限 600s，已经贴着天花板。迁移到 FastAPI 后用 StreamingResponse + asyncio，取消 600s 限制；但仍要配 client 超时 5 分钟，SSE 心跳保活 10s，前端断线自动重连。灰度期必须并行跑新旧两条链路对比输出差异。
Layer 2 辩论严格顺序依赖
7 位大师必须按 价值守门人 → 成长猎手 → 周期判官 → 反身性猎手 → 全天候架构师 → 宏观动量派 → 生意模式派 顺序执行。每个 master 的 prompt 注入 debateTranscript（前序所有大师发言），不能用 asyncio.gather 并行，只能 async for。改顺序或并行会破坏辩论逻辑。
港股代码三套格式互转
内部/用户: 01709.HK / 0700.HK（保留原长度）→ Yahoo: 1709.HK / 0700.HK（5 位去首零）→ AKShare: 01709 / 00700（5 位纯数字无后缀）。硬编码在 hk-code.ts 的映射表必须原样移植到 Python，不能重写逻辑。常见热门：0700=腾讯 / 9988=阿里 / 3690=美团 / 1810=小米 / 01709=德林控股。
AI Gateway 双通道路由逻辑
检测到 ANTHROPIC_API_KEY 时，Claude 模型走 Anthropic 原生 API（SSE 需转换为 OpenAI 格式）；其他模型或无 key 时走云雾 yunwu.ai/v1/chat/completions（OpenAI 兼容）。tool calling 时 Anthropic max_tokens 必须 ≥ 16384，否则 JSON 截断。
外部 API Rate Limit
Yahoo Finance：无正式限制，高频会被 block，stock-quotes 60s 轮询时建议加 jitter。Finnhub：免费 60 req/min，需限流中间件。AKShare：部分接口（stock_zh_a_hist）超时率高，脚本层面已加重试，迁移时保留。Anthropic：按订阅额度，429 失败需指数退避。
SERVICE_ROLE_KEY 的使用边界
只有 6 个函数真正需要高权限 key：predict-stock（写跨用户预测）、admin-users（管理员操作）、toggle-subscription（修改订阅）、fetch-news（写无用户上下文）、orchestrator（写日志）、chat（读全局 config）。新后端里把 service-role client 封装成独立模块，只在这几处导入，避免泄露。
SSE 事件格式必须与前端一致
前端 useOrchestrator.ts 按 data: {...}\n\n 逐行解析，事件 type 字段严格匹配枚举。迁移后用 FastAPI StreamingResponse 时，yield f"data: {json.dumps(event)}\n\n"。结尾必须发 data: [DONE]\n\n（前端会识别并跳过）。不要改事件 type 名称或字段 camelCase / snake_case。
Prompt 迁移：TS → YAML 的等价性
15 个 prompt 文件迁移到 YAML 时，文本内容必须 1:1 复制，不要「优化」。哪怕是空格、换行、标点都影响模型输出（大师 prompt 行为敏感）。推荐写一个校验脚本：读 TS → 读 YAML → 字符串 diff 为 0 才通过。
report_tasks 异步状态机
Python worker 与前端通过 report_tasks 表的 status / progress 字段协作：pending → running → phase_1 → phase_2 → phase_3 → phase_4 → done | error。前端用 Supabase Realtime 订阅行变化。迁移时保留 realtime 订阅，不要改 worker 写回机制，否则前端进度条失效。
资产路由 DB 策略表
orchestrator 的 Router LLM 逻辑依赖 orchestrator_strategies 表：按优先级匹配市场（HK/CN/US）+ 关键词 → 决定候选大师集合和 stance 分配。这张表的数据先别迁（Supabase 直连读取即可），但要把表结构文档化：字段包含 priority / market / keywords / candidate_masters / use_router_llm / stance_overrides。

🎯 预测准确率改进
1

分级评分体系替代 boolean 判断

现状：checkCorrect() 只看方向对不对（涨了就算看多正确），不衡量置信度校准和幅度准确性
方案：引入 score: 0-100 连续评分。方向正确 +40，目标价误差 <5% 再 +30，confidence 与实际吻合 +30。在 stock_prediction 表新增 score、price_error_pct 字段。
-- stock_prediction 新增字段 ALTER TABLE stock_prediction ADD COLUMN score REAL; -- 0-100 综合评分 ALTER TABLE stock_prediction ADD COLUMN price_error_pct REAL; -- 目标价偏差百分比
涉及： use-stock-predictions.ts · 新增 migration
2

预测反馈闭环 — 回流到 AI Prompt

现状：预测生成后就结束，验证结果从不喂回模型。这是最大的架构缺口——系统永远不会从错误中学习。
方案：构建 Prediction Feedback Loop：按 agent × sector × horizon 聚合历史准确率，注入 orchestrator prompt 作为 calibration context。高准确率 agent 在 synthesizer 中获得更高权重。
stock_prediction (verified) → agent_accuracy_stats 物化视图 (agent × sector × horizon) → orchestrator 启动时查询 → 注入 system prompt: "你过去 30 天对科技股看多准确率 62%，请据此调整置信度" → synthesizer 加权: final = Σ(confidence × historical_accuracy × signal)
涉及： 新增 agent_accuracy_stats 物化视图 · orchestrator/index.ts prompt 注入 · synthesizer 加权逻辑
3

Ensemble 动态权重合成

现状：Synthesizer 平等对待所有大师发言，但不同大师在不同市场/行业的准确率差异显著
方案：两级方案：① Prompt 级——synthesizer prompt 注入各 master 历史准确率，让 LLM 自行加权。② 数值级——final_score = Σ(master_confidence × historical_accuracy × direction_signal)，LLM 合成定性分析，数值公式决定最终方向。
涉及： orchestrator/index.ts synthesizer 逻辑
4

预测基准价修正

现状：price_at_prediction 统一取预测时刻价格，盘后分析时该价格是收盘价而非次日开盘价，导致验证偏差
方案：记录 prediction_market_state（盘中/盘前/盘后），验证时使用对应基准价——盘后预测以次日开盘价为基准，避免系统性偏差。
涉及： predict-stock/index.ts · stock_prediction 新增字段

渐进式定价 — 降低单次成本提高频率

方案：重构定价为渐进式消耗——每条消息都产生微小成本，培养付费意识；深度分析降低门槛，提高频率，总消耗反而更大。

触发式消耗场景 — 系统推动用户消耗

现状：只有用户主动发起才消耗 credits，没有系统推动消耗的机制
方案：四个触发式场景：
• 预测到期提醒——预测快过期时推送通知，引导用户查看结果并做新预测（1 credit）
• 持仓异动监控——关注股票出现异动，自动触发轻量分析（1 credit，需确认）
• 每日 AI 简报——每天早上生成关注列表摘要（2 credits）
• 大师观点追踪——上次辩论的大师观点有新变化时通知（1 credit）
在 credit_pricing 表加新 action 即可，不改核心架构。
涉及： credit_pricing 新增 actions · 新增推送/通知服务 · 新增 cron Edge Function
7

正反馈循环 — 让 Credit 消耗有"成瘾性"

现状：用完就停，没有激励用户继续的机制。Credit 是纯消耗品，无回报感。
方案：三层正反馈设计：
• 准确率排行榜——展示用户预测准确率排名，激励更多预测（每次消耗 credit）
• 连续使用奖励——连续 7 天使用，奖励 bonus credits，降低流失
• 预测对了返 credit——预测准确返还部分 credit，形成"越准越多→越多越用→越用越准"飞轮
涉及： 新增 user_streaks 表 · prediction-tracker 返 credit 逻辑 · 排行榜 UI 组件
